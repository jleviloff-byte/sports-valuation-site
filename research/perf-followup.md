# Perf follow-up: split the team data out of the main bundle

Not done in `transactions-update`. This is the plan for its own branch.

## The problem

Every byte of team data ships in the initial JavaScript bundle. Lighthouse (production preview, 2026-09-27) on this branch:

| Page | Perf | LCP | Main chunk |
|---|---|---|---|
| /recent-sales | 49 | 7.3 s | `index-*.js` 1,660 KB (360 KB gzip before this branch, now larger) |
| /forbes-breakdown | 57 | 7.3 s | same |
| /?team=seattle-seahawks | 27 | 59 s (lab, throttled) | same, plus Wikimedia hero images |

The main chunk was 1,291 KB on `main` before this branch. This branch added roughly 370 KB of source data to it: `sale-history.js` (350 KB), `transactions.js` (141 KB), `forbes-proxies.js` (90 KB), `forbes-breakdown.js` (44 KB), `forbes-commentary.js`, `divisions.js`. The pre-existing data is larger still: six `enrichments-*.js` files (about 930 KB), six `supplements-*.js` (about 300 KB), `images.js` (65 KB), `teams.js`/`teams-base.js` (92 KB), driver scores, payrolls.

Why it is all in one chunk: `data/allTeams.js` imports every enrichment and supplement file synchronously and derives the 174-team list at module load, and `App.jsx` imports `allTeams` at the top. `enrichments.js` also uses `import.meta.glob(..., { eager: true })` for the supplements, which forces them in.

## What each page actually needs

| Consumer | Needs at first paint | Needs later |
|---|---|---|
| Home (explorer, ticker, map, compare) | Per team: name, league, city, currentValuation, growth figures, valuationDrivers, rankings, payroll, ownsStadium, stadiumName, market/media/brand tiers | Nothing else until a profile opens |
| Profile panel (`TeamDetailPanel`) | The one team's enrichment (stadium, media, ownership, brand, onField, analystNotes, factorNarratives), its saleHistory, its lastSale, its forbesBreakdown, its proxies, the league's breakdown stats | |
| /recent-sales | `transactions.js` (46 deals), team name/league/logo for those teams, saleHistory for the 30 shown | |
| /forbes-breakdown | `forbes-breakdown.js`, `forbes-proxies.js`, team names, one league at a time | |
| Methodology | Premium medians (from transactions) | |

The home page needs a small, flat record per team. Everything else is per team or per page.

## Plan

### Step 1: precompute the light team list at build time

Add `scripts/build-teams-index.mjs` that runs the derivation now inside `allTeams.js` (deriveTeam, rankings, payroll join, Forbes headline override) and writes `data/teams-index.json`: 174 flat records with only the fields the home page reads (list above). Target under 60 KB raw. `allTeams.js` becomes a thin import of that JSON plus `precedentComps` (which only needs `transactions.js`, 141 KB; shrink it by moving `investmentCase.text`, `details` and `drivers[].text` to a per-deal chunk, see step 3).

Keep the build script in `npm run build` (`prebuild`) so the JSON is never stale.

### Step 2: lazy-load enrichment per league

Split the profile data into per-league chunks with dynamic imports:

```js
// data/loadTeamDetail.js
const loaders = {
  NFL: () => import('./detail/nfl.js'),
  NBA: () => import('./detail/nba.js'),
  ...
}
export async function loadTeamDetail(team) {
  const mod = await loaders[team.league]()
  return mod.default[team.id]   // enrichment + supplement merged, saleHistory, proxies, forbesBreakdown
}
```

`data/detail/<league>.js` is generated by the same build script from `enrichments-<league>.js`, `supplements-<league>.js`, `sale-history.js`, `forbes-proxies.js`, `forbes-breakdown.js`, `forbes-commentary.js`, keyed by team id. Six chunks of roughly 250 to 350 KB each, loaded only when a profile in that league opens (or prefetched on hover of a team card). `TeamDetailPanel` gets a `useTeamDetail(team)` hook with a skeleton while the chunk loads; `getEnrichment(name)` callers move to the hook.

Alternative if per-league is still too heavy: one JSON per team under `public/data/teams/<id>.json` (174 files, 5 to 15 KB each) fetched on profile open. Simpler to cache, but 174 build outputs and no tree-shaking. Per-league chunks are the better first cut; per-team files are the fallback if a league chunk exceeds 400 KB.

### Step 3: route-level data

- `/recent-sales`: import `transactions.js` inside the page module (it is already route-split); move deal prose (`drivers[].text`, `investmentCase.text`, `details`) into `data/transactions-detail.js` loaded by the page, leaving the `precedentComps` input at about 20 KB.
- `/forbes-breakdown`: the page already loads `forbesBreakdown-*.js` (92 KB) lazily; keep `forbes-breakdown.js` and `forbes-proxies.js` out of `allTeams.js` by moving `t.forbesBreakdown` and league stats into the league detail chunk from step 2.
- `sale-history.js` (350 KB) is only read by profiles and the Recent Sales timeline: it belongs in the per-league detail chunks, with the 30 Recent Sales teams' histories duplicated into `transactions-detail.js` (about 60 KB).

### Step 4: images

Profile hero and iconic-moment images are Wikimedia `Special:FilePath` URLs that redirect twice (`Special:FilePath` → `Special:Redirect/file` → `upload.wikimedia.org`) and carry `loading="lazy"` even when the panel is the landing view (`/?team=`). Lighthouse marks them as the LCP element at 16 to 89 s under throttling.

Cookie finding (checked 2026-09-27): every hop sets cookies, including the final `upload.wikimedia.org` response (`WMF-Uniq`, SameSite=None, one-year expiry). So resolving the redirects at build time (MediaWiki `imageinfo` API, 50 titles per call) removes two hops and the `NetworkProbeLimit`/`GeoIP` cookies but still fails Lighthouse's third-party-cookies audit on one cookie per image. Clearing the audit requires serving the images first-party: mirror the ~350 files (logos, stadiums, iconic moments) into `public/img/` at build time from the resolved upload URLs, respecting Wikimedia's rate limits and keeping the attribution captions, or route them through Vercel's image optimizer. Team logos already come from ESPN's CDN (no cookies) for every team except a few MLS clubs, which is why /recent-sales only tripped on one logo.

Also on the hero: add `fetchpriority="high"` and drop `loading="lazy"` when the panel opens from a deep link, and request a sized thumbnail (`/thumb/.../1200px-...`) instead of the original.

### Step 5: verify

Targets on the same Lighthouse setup: main chunk under 500 KB raw, perf 80+ on /recent-sales and /forbes-breakdown, profile open under 1 s on a warm cache. Add `npx vite build --report` (rollup-plugin-visualizer) to the branch to confirm nothing from `data/` lands in `index-*.js` except `teams-index.json` and the slim `transactions.js`.

## Order of work

1. Step 1 (build script and teams index) with no UI change; confirm home page renders identically.
2. Step 3 for `/recent-sales` (already route-split, lowest risk).
3. Step 2 (per-league detail chunks) with the profile hook and skeleton.
4. Step 4 images.
5. Step 5 measure; then delete the now-unused eager imports in `enrichments.js`.
